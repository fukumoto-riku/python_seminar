# `self_code` のTitanic生存予測コード解説

## 1．概要

### 1.1 目的

このディレクトリの中心となる [`titanic_f1_competition.ipynb`](./titanic_f1_competition.ipynb) は，`train_titanic.csv` に含まれる712人の乗客情報と生存ラベルを使って，`test_titanic.csv` の179人が生存したかを予測するノートブックである．

予測対象の `Survived` は，死亡を `0`，生存を `1` とする二値分類である．正式な評価指標は，生存者を正例としたF1スコアである．F1スコアは，生存と予測した結果の正確さを示す適合率と，実際の生存者をどれだけ見つけたかを示す再現率のバランスを評価する．

この実装は，特徴量とモデルを幅広く比較した後，Applicability Domain（AD）を使って学習データに近い領域と遠い領域の性能を確認する．最終的に，全体OOF性能を重視する案，ADを考慮して別モデルを選ぶ案，生存者の取り逃がしを減らす案の3種類を提出する．

### 1.2 コード全体の流れ

ノートブックは，おおまかに次の順序で処理を行う．

1. ライブラリ，乱数シード，交差検証，Optunaの設定を決める．
2. `train_titanic.csv` と `test_titanic.csv` を読み込み，行数，列，ID，ラベルを検査する．
3. 欠損値，生存率，数値特徴の分布などを確認する．
4. 敬称，家族人数，チケット人数，姓の人数，客室，運賃などから特徴量を作る．
5. 特徴量セット，敬称のまとめ方，家族人数区分をOOF評価で比較する．
6. 採用特徴量で8種類のモデルとクラス重みを比較する．
7. 6モデルをOptunaで調整し，上位trialを複数の乱数シードで再評価する．
8. 各モデルのOOF予測，F1最適閾値，予測の多様性を比較する．
9. 異種モデルのsoft votingも作り，単一モデルと比較する．
10. 採用モデルを学習データ全体で3回学習し，テスト生存確率を平均する．
11. 6個の数値特徴量とk近傍平均距離を使ってAD内外を判定する．
12. 各モデルのOOF性能をAD内外に分け，提出候補を選ぶ．
13. LightGBM，XGBoost，LightGBMの閾値variantという3提出を保存する．
14. AD結果，モデル別AD性能，提出間の比較結果もCSVへ保存する．
15. 正解配布後は [`answer.ipynb`](./answer.ipynb) でF1スコアを確認する．

入力から出力までの関係は次のようになる．

```text
train_titanic.csv
    ↓ 特徴量profile比較・8モデル比較・Optuna・OOF閾値選択
採用特徴量とモデル設定
    ↓ 3 seedで全train再学習
test_titanic.csvに対するモデル別生存確率
    ↓ OOF全体性能とAD内外性能を参照して提出案を選択
3種類の提出CSV
```

## 2．3つの予測方法

モデルは，各乗客が生存する確率を出力する．各提出では，確率がそれぞれの閾値以上なら `Survived=1`，未満なら `Survived=0` とする．

| 提出ファイル | 予測方法 | 簡潔な説明 | 閾値 | 現在の生存予測数 |
| --- | --- | --- | ---: | ---: |
| [`submission_1_best_overall.csv`](./submission_1_best_overall.csv) | 全体性能最良 | 全体OOF F1が最も高いLightGBMを使う | `0.474` | 62人 |
| [`submission_2_ad_selected.csv`](./submission_2_ad_selected.csv) | ADを考慮した別モデル | 上位候補から，提出1と異なるXGBoostを選ぶ | `0.458` | 62人 |
| [`submission_3_threshold_variant.csv`](./submission_3_threshold_variant.csv) | Recall寄りの閾値variant | 提出1と同じLightGBM確率で閾値だけを下げる | `0.444` | 65人 |

3提出はいずれも，採用特徴量profile `C_rare_simple3` を使う．単一の学習結果に依存しないよう，シード42，123，2026で全学習データを3回学習し，テストデータの生存確率を平均する．

### 2.1 提出1：LightGBMによる全体性能最良モデル

提出1は，OOF予測に対する全体F1スコアが最も高いモデルを選ぶ．現在はLightGBMが選ばれている．

LightGBMは，前の決定木が間違えた例を次の決定木で補う勾配ブースティングの一種である．小さな決定木を順番に追加し，複雑な関係を学習する．

現在の全体OOF F1は `0.8115`，閾値は `0.474` である．3 seedで学習したLightGBMの平均確率が `0.474` 以上なら生存と予測する．

### 2.2 提出2：ADを考慮して選んだXGBoost

提出2では，まず全体OOF F1が最良値から `0.02` 以内のモデルだけを候補にする．次に，テストデータのAD内外比率を反映した `Test_AD_Weighted_Score` で候補を並べる．

現在はLightGBMがこの補助スコアでも首位であるが，提出1と同じモデルになる．予測の異なる案を残すため，候補内で次に高い別モデルであるXGBoostを選んでいる．

XGBoostも勾配ブースティング決定木であるが，木の作り方や正則化がLightGBMと異なる．現在の全体OOF F1は `0.8079`，閾値は `0.458` である．

ADは乗客ごとにLightGBMとXGBoostを切り替えるためには使わない．179人全員を同じXGBoostで予測する．

### 2.3 提出3：LightGBMのRecall寄り閾値variant

提出3は，提出1と独立した別モデルではない．提出1と同じLightGBMのテスト生存確率を使い，判定閾値だけを `0.474` から `0.444` へ `0.03` 下げる．

閾値を下げると，生存と判定される乗客が増える．一般に，実際の生存者の取り逃がしが減って再現率が上がりやすい一方，死亡者を生存と誤判定する件数も増える可能性がある．提出3は，この適合率と再現率の違いを試す案である．

## 4．特徴量と前処理

### 4.1 特徴量profileの比較

すべての特徴量を最初から採用するのではなく，複数のprofileをOOF評価で比較する．大きく分けると次の4段階である．

- Set A：客室等級，性別，年齢，家族数，運賃，乗船港などの基本特徴
- Set B：敬称，家族人数，子ども，客室情報を追加
- Set C：チケット人数，姓の人数，性別・等級などの相互作用を追加
- Set C extended：年齢帯，運賃帯，親役割，追加の組合せなどを候補として追加

さらに，少数敬称を意味ごとに分けるか一律 `Rare` にまとめるか，家族人数を3区分または4区分にするかも比較する．現在の採用profileは `C_rare_simple3` である．

### 4.2 採用された23特徴

`C_rare_simple3` は，数値15列とカテゴリ8列の合計23特徴を使う．

#### 数値特徴15列

- `Pclass`：客室等級
- `Age`：補完後の年齢
- `SibSp`，`Parch`：同乗家族の人数
- `FareLog`：運賃の対数
- `AgeMissing`：元の年齢が欠損していたか
- `FamilySize`：本人を含む家族人数
- `IsAlone`：単独乗船か
- `IsChild`：16歳未満か
- `HasCabin`：客室番号が記録されているか
- `TicketGroupSize`：学習側に同じチケットを持つ乗客が何人いるか
- `SharedTicket`：同じチケットを複数人が持つか
- `FarePerPerson`：運賃を同一チケット人数で割った値
- `SurnameGroupSize`：学習側に同じ姓を持つ乗客が何人いるか
- `HasFamilySurname`：同じ姓の乗客が複数いるか

#### カテゴリ特徴8列

- `Sex`
- `Embarked`
- `Title`
- `FamilyGroup`
- `Deck`
- `TicketPrefix`
- `Sex_Pclass`
- `Title_Pclass`

生の `Name`，姓，`Ticket`，`Cabin` は，特徴を抽出した後にモデル入力から除外する．`PassengerId` も提出時の対応付けにだけ使う．

### 4.3 敬称

`Name` から敬称を抽出し，`Mr`，`Mrs`，`Miss`，`Master` を残す．それ以外は `Rare` にまとめる．敬称は性別だけでなく，年齢層，婚姻状態，社会的属性を間接的に表す．

### 4.4 家族情報

`FamilySize` は次の式で求める．

```text
FamilySize = SibSp + Parch + 1
```

採用profileでは，本人だけを `Alone`，2～4人を `Small`，5人以上を `Large` とする．`IsAlone` と `IsChild` も別の0／1特徴として持つ．

### 4.5 チケット，姓，運賃，客室

同じチケットや姓を持つ乗客は，家族または同行者である可能性がある．`TicketGroupSize` と `SurnameGroupSize` は，この関係を人数として表す．人数の集計は，交差検証の各学習foldだけで行う．

`FarePerPerson` は，運賃を同じチケットを持つ人数で割った値である．`FareLog` は，運賃の大きな値の影響を小さくするために `log1p` 変換した値である．

`Cabin` からは先頭文字の `Deck` と，情報の有無を表す `HasCabin` を作る．出現回数が少ないデッキやチケット接頭辞は，学習fold内の件数に基づいて共通カテゴリへまとめる．

### 4.6 欠損値の補完

`TitanicFeatureEngineer.fit()` は，交差検証の学習foldだけから補完値を学習する．

- `Age`：敬称と客室等級ごとの中央値，敬称ごとの中央値，客室等級と性別ごとの中央値，全体中央値の順に使う．
- `Fare`：客室等級ごとの中央値，次に全体中央値を使う．
- `Embarked`：学習側の最頻値を使う．

検証foldやテストデータの値を含めて中央値や最頻値を計算しない．

### 4.7 モデル別の前処理

CatBoostはカテゴリ列を文字列のまま受け取り，モデル内部で処理する．ほかの7モデルはOne-hot encodingでカテゴリを0／1列へ変換する．未知カテゴリは無視できる設定にする．

ロジスティック回帰とRBF-SVMは値の尺度に影響されるため，数値列を `StandardScaler` で標準化する．決定木系モデルには標準化を行わない．

特徴量作成，補完，カテゴリ変換，標準化，モデルを1つのPipelineとして扱うため，各foldの学習部分だけで前処理をfitできる．

## 5．モデル評価と選択

### 5.1 OOF予測

OOF予測は，各乗客について，その乗客を学習に使っていないfoldのモデルが出した生存確率である．層化5-fold交差検証により，全712人へ学習時未使用の予測確率を割り当てる．

通常実行ではシード42，123，2026の3種類でOOF評価を繰り返す．単一のデータ分割だけでモデルを判断せず，平均性能とばらつきを見るためである．

### 5.2 F1用の閾値

`select_stable_threshold()` は，まず `0.10` から `0.90` を探索し，最良値の周辺をさらに細かく調べる．最大F1との差が `0.002` 以内にある安定域から閾値を選ぶ．

閾値を下げると生存予測が増えて再現率が上がりやすく，閾値を上げると生存予測が減って適合率が上がりやすい．

### 5.3 特徴量profileの選択

まずCatBoost，ExtraTrees，ロジスティック回帰を代表モデルとして，各特徴量profileをシード42で比較する．上位profileはシード123，2026でも再評価し，モデルが変わっても安定している構成を選ぶ．現在は `C_rare_simple3` が採用されている．

### 5.4 比較する8モデル

| モデル | 種類 | 主な特徴 |
| --- | --- | --- |
| CatBoost | ブースティング | カテゴリ変数を直接扱える |
| LightGBM | ブースティング | 高速で複雑な非線形関係を扱える |
| XGBoost | ブースティング | 正則化が豊富で過学習を抑えやすい |
| HistGradientBoosting | ブースティング | scikit-learnで利用できる勾配ブースティング |
| ExtraTrees | バギング | ランダム性の高い多数の決定木を平均する |
| Random Forest | バギング | データを変えて作った多数の決定木を平均する |
| Logistic Regression | 線形モデル | 単純で比較的説明しやすい |
| RBF-SVM | カーネルモデル | 曲線的な境界を学習できる |

クラス数の偏りに対応するため，重みなし，`balanced`，生存クラスを1.2倍する設定も比較する．

### 5.5 Optuna

モデルごとに事前設定する値をハイパーパラメータという．Optunaは，ハイパーパラメータの組合せを試し，OOF評価が高い設定を探索する．

このコードでは，CatBoost，LightGBM，XGBoost，HistGradientBoosting，ExtraTrees，Random Forestの6モデルを調整する．ロジスティック回帰とRBF-SVMは，初期比較で得た設定を使う．

完全モードでは，各モデルについて30 trialをシード42で探索する．上位3 trialをシード42，123，2026で再評価し，次の安定性を考慮した値で採用設定を決める．

```text
採用基準 = OOF F1 - 0.25 × fold間F1の標準偏差
```

### 5.6 soft voting

複数モデルのOOF確率の相関と誤分類の違いを確認し，異なる種類のモデルを重み付き平均するsoft votingも探索する．現在の候補は次の3モデルである．

- LightGBM：重み `0.2`
- Random Forest：重み `0.6`
- Logistic Regression：重み `0.2`

soft votingのOOF F1は `0.8014`，閾値は `0.384` である．ただし，現在の3提出には採用されていない．ノートブックは比較候補として評価し，AD性能表には含めている．

### 5.7 選択バイアス

特徴量profile，モデル，ハイパーパラメータ，閾値を同じ712人のOOF結果を使って繰り返し比較している．検証foldの正解がモデル学習へ直接混ざるデータリークは防いでいるが，厳密なNested CVではないため，最終OOF F1には選択バイアスが残る可能性がある．

OOF値はモデル比較の目安であり，未知のテストデータで同じF1が得られる保証ではない．

## 6．Applicability Domain分析

### 6.1 ADとは何か

Applicability Domain（AD）は，予測対象が学習データと似た領域にあるかを確認する目安である．AD内の乗客は学習例に比較的近く，AD外の乗客は学習例から遠い．AD外だから必ず誤るわけではないが，似た学習例が少ないため予測を慎重に見る必要がある．

### 6.2 ADに使う特徴

モデル本体の23特徴すべてではなく，説明しやすい次の6個の数値特徴だけを使う．

- `Pclass`
- `Age`
- `FareLog`
- `FamilySize`
- `TicketGroupSize`
- `SurnameGroupSize`

欠損値は学習データの中央値で補完し，学習データだけでfitした `StandardScaler` により平均0，標準偏差1へそろえる．値の単位が異なる特徴同士を，距離計算で公平に扱うためである．

### 6.3 k近傍平均距離

各乗客について，標準化後の空間で近い5人までの距離を平均する．最も近い1人だけでなく5人を見ることで，周囲に複数の似た学習例があるかを表す．

学習データでは自分自身との距離0を除外する．テストデータでは，近傍候補を学習データだけにする．

### 6.4 AD境界

学習データのk近傍平均距離の95パーセンタイルを境界とする．現在の境界値は `1.242118` である．

- 距離が境界以下：AD内
- 距離が境界より大きい：AD外

全学習データ基準の現在の件数は次のとおりである．

| データ | AD内 | AD外 |
| --- | ---: | ---: |
| 学習データ | 676人（94.94%） | 36人（5.06%） |
| テストデータ | 167人（93.30%） | 12人（6.70%） |

### 6.5 fold単位のOOF用AD

各モデルのOOF性能をAD内外に分けるときは，各foldの学習部分だけで補完，標準化，近傍モデル，95パーセンタイル境界を作る．検証fold自身をAD基準の作成へ使わないためである．

現在のfold単位判定では，AD内686人，AD外26人である．全学習データを基準にした簡易判定との一致率は95.79%である．

### 6.6 `Test_AD_Weighted_Score`

各モデルについて，OOFのAD内F1とAD外F1を計算する．次に，テストデータのAD内外比率を重みとして補助スコアを作る．

```text
Test_AD_Weighted_Score
    = testのAD内比率 × OOFのAD内F1
    + testのAD外比率 × OOFのAD外F1
```

この値はテストデータの正解を使っていないため，テストF1の実測値ではない．テストデータの多くがAD内か，AD外かという構成をモデル比較へ反映するための簡易指標である．

一方で，正解ラベルは使っていなくても，テストデータの説明変数から得たAD内外比率を提出2のモデル選択に利用している．レギュレーションの「テストデータの情報をモデル選択に漏らさない」を広く解釈すると，完全なtrain-only選択とはいえない可能性がある．この点を許容しない場合は，ADを提出後の信頼性分析だけに使い，モデル選択は全体OOF性能だけで完結させる必要がある．

## 7．最終学習と出力

### 7.1 全学習データでの再学習

## 9．実行方法と注意点

### 9.1 実行方法

このディレクトリを作業ディレクトリとして環境を同期し，ノートブックを上から順に実行する．

```bash
uv sync
uv run jupyter notebook titanic_f1_competition.ipynb
```

構造確認を短時間で行う場合は，次のように短縮設定を有効にできる．

```bash
TITANIC_FAST_MODE=1 uv run jupyter notebook titanic_f1_competition.ipynb
```

完全評価では `FAST_MODE=False`，`CV_SEEDS=(42, 123, 2026)`，5-foldであることを確認する．Optunaと複数seed評価を含むため，通常実行には長い時間がかかる．

### 9.2 `answer.ipynb` の位置付け

`answer.ipynb` は正解配布後だけ使用する．提出CSVと正解を `PassengerId` で結合し，F1スコア，正解数，混同行列を表示する．同じ採点関数が3セルに重複しており，各セルで別の提出CSVを採点する．

不足または余分なIDは警告するが，重複ID，179行，0／1整数を厳密に停止条件として検査するわけではない．提出形式の保証は本体ノートブック側の `validate_and_save_submission()` で行う．

### 9.3 再実行時の注意

- `Path.cwd()` を使うため，`self_code` を作業ディレクトリにして実行する．
- 既存CSVと再実行結果が異なる場合は，上書きせず `FileExistsError` で停止する．
- 提出CSVのラベルを答え合わせ後に人手で変更しない．
- AD外の件数は少ないため，AD外F1は少数の予測変化で大きく変わる．
- `Test_AD_Weighted_Score` をテストF1の予測値として扱わない．
- `main.py` は機械学習の実行入口ではない．

## 10．要点

この実装は，23個の採用特徴，8モデル比較，Optuna，複数seedのOOF評価，F1閾値最適化，k近傍距離によるAD分析を組み合わせている．最終的には，全体OOF F1が最良のLightGBM，ADを考慮して選んだ別モデルのXGBoost，同じLightGBMの閾値を下げたRecall寄りvariantという3提出を作る．

ADは乗客ごとにモデルを切り替える仕組みではなく，モデル候補の性能を学習データに近い領域と遠い領域へ分けて確認する分析である．また，テストのAD構成を提出2の選択に使うため，完全なtrain-onlyモデル選択との違いを理解したうえで結果を読む必要がある．
