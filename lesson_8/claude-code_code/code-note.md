# `claude-code_code` のTitanic生存予測コード解説

## 1．概要

### 1.1 目的

このディレクトリの中心となる [`titanic_survival_prediction.ipynb`](./titanic_survival_prediction.ipynb) は，`train_titanic.csv` に含まれる712人の乗客情報と生存ラベルを使って，`test_titanic.csv` の179人が生存したかを予測するノートブックである．

予測対象の `Survived` は次の二値で表される．

- `0`：死亡
- `1`：生存

評価指標は，生存者を正例としたF1スコアである．F1スコアは，生存と予測した人のうち実際に生存していた割合である適合率と，実際の生存者をどれだけ見つけられたかを表す再現率のバランスを評価する．

### 1.2 コード全体の流れ

ノートブックは，おおまかに次の順序で処理を行う．

1. ライブラリを読み込み，乱数シードを設定する．
2. `train_titanic.csv` と `test_titanic.csv` を読み込む．
3. 欠損値，生存率，性別，客室等級，家族人数などを確認する．
4. 氏名，家族，チケット，客室，運賃から機械学習用の特徴量を作る．
5. 交差検証の各foldで，学習側のデータだけを使って欠損補完値やグループ統計を計算する．
6. 6種類のモデルについてハイパーパラメータを比較する．
7. Out-of-Fold（OOF）予測を作り，AP，AUC，F1スコアを比較する．
8. OOF予測だけを使って，生存と判定する確率の閾値を決める．
9. スタッキング，ソフト投票，最良単一モデルの3方式を作る．
10. 採用したモデルを学習データ全体で再学習し，テストデータを予測する．
11. 179人分の `PassengerId` と `Survived` を持つ3つの提出CSVを保存する．
12. 正解配布後は [`answer.ipynb`](./answer.ipynb) でF1スコアを確認する．

入力から出力までの関係は次のようになる．

```text
train_titanic.csv
    ↓ 特徴量作成・交差検証・モデル選択・閾値選択
学習済みの6モデル
    ↓ test_titanic.csvを予測
6モデルの生存確率
    ↓ 単一モデル／確率平均／2段階学習
3種類の提出CSV
```

## 2．3つの予測方法

モデルは最初から `0` または `1` を出すのではなく，各乗客の生存確率を出す．最終的には，生存確率が方式ごとに決めた閾値以上なら `1`，未満なら `0` とする．

| 提出ファイル | 予測方法 | 簡潔な説明 | 閾値 | 現在の生存予測数 |
| --- | --- | --- | ---: | ---: |
| [`submission_stacking.csv`](./submission_stacking.csv) | スタッキング | 6モデルの予測を別のモデルへ入力し，組み合わせ方を学習する | `0.385` | 68人 |
| [`submission_voting.csv`](./submission_voting.csv) | ソフト投票 | 成績上位5モデルの生存確率を同じ重みで平均する | `0.300` | 79人 |
| [`submission_best_single_extratrees.csv`](./submission_best_single_extratrees.csv) | 最良単一モデル | APが最も高かったExtraTreesだけで予測する | `0.270` | 81人 |

### 2.1 スタッキング

スタッキングは，複数モデルの予測を材料にして，さらに別のモデルが最終予測を作る方法である．

このコードでは，ロジスティック回帰，Random Forest，ExtraTrees，HistGradientBoosting，LightGBM，XGBoostの6モデルについて，学習に使われていない乗客に対するOOF生存確率を作る．6個の確率を新しい6列の特徴量とみなし，2段目のロジスティック回帰へ入力する．

2段目のロジスティック回帰は，各モデルをどの程度重視すればよいかを学習する．正則化の強さ `C` は `0.1`，`0.3`，`1.0`，`3.0` を比較し，現在の実行結果では `C=3.0` が選ばれている．

### 2.2 ソフト投票

ソフト投票は，複数モデルの生存確率を平均する方法である．多数決のように最終ラベルだけを数えるのではなく，確率の大きさも利用する．

参加モデルは，OOFのAverage Precision（AP）が最良モデルとの差 `0.015` 以内にあるモデルから選ぶ．現在の実行では次の5モデルが参加している．

- Logistic Regression
- Random Forest
- ExtraTrees
- LightGBM
- XGBoost

HistGradientBoostingはAPが基準に届かなかったため，現在のソフト投票には含まれていない．5モデルの確率はすべて同じ重みで平均する．

### 2.3 最良単一モデル

最良単一モデルは，複数モデルを組み合わせず，選ばれた1種類のモデルだけで予測する方法である．

このコードの `best_single` はF1スコアではなく，OOFの平均APが最大のモデルを選ぶ．現在はExtraTreesが選ばれている．ExtraTreesは，データや特徴量の選び方に乱数を使って多数の決定木を作り，それらの結果を平均するモデルである．

乱数による予測の揺れを抑えるため，シード42，142，242でExtraTreesを3回学習し，3つの生存確率を平均する．各モデルは600本の木を持つため，合計では1800本の決定木の予測を平均していることになる．

## 4．処理の詳細

### 4.1 ライブラリと再現性

ノートブックでは，pandasとNumPyによるデータ処理，scikit-learnによる交差検証とモデル構築，LightGBMとXGBoostによる勾配ブースティングを使用する．`SEED=42` を基準として，データ分割やモデルの乱数を固定する．

`pyproject.toml` ではPython 3.11以上と，主に次のライブラリを管理している．

- pandas，NumPy
- scikit-learn
- LightGBM，XGBoost
- Matplotlib，Seaborn
- Jupyter関連ライブラリ

### 4.2 データの読み込みと確認

学習データは712行12列，テストデータは179行11列である．学習データにだけ目的変数 `Survived` が含まれる．

データ読み込み後は，主に次を確認する．

- データ件数と列名
- 各列の型と欠損数
- `Survived` の0と1の件数
- 性別や客室等級ごとの生存率
- 年齢，運賃，家族人数と生存の関係

`PassengerId` は提出結果と乗客を対応付けるために保持するが，単なる識別番号であるためモデルの特徴量には使わない．

### 4.3 特徴量エンジニアリング

元の列をそのまま使うだけでなく，乗客の背景や同行関係を表す特徴量を作る．最終的な `transform_features()` の出力は42列である．

#### 敬称と氏名

`Name` から `Mr`，`Mrs`，`Miss`，`Master` を抽出し，その他の少数敬称は `Rare` にまとめる．敬称は性別，年齢層，婚姻状態などを間接的に表す．

さらに，氏名の長さを `NameLength`，カンマより前の部分を姓として取得する．姓は家族グループを推定するために使うが，生の氏名や姓そのものは最終的な数値行列へ直接渡さない．

#### 家族情報

`FamilySize` は次の式で求める．

```text
FamilySize = SibSp + Parch + 1
```

本人だけなら `solo`，2～4人なら `small`，5人以上なら `large` とする．`IsAlone` は単独乗船かを0または1で表す．

#### チケットと運賃

学習側データに同じ `Ticket` が何件あるかを `TicketGroupSize` とする．`Fare` はチケット全体の料金である可能性があるため，チケット人数や家族人数で割った値も作る．運賃は分布の偏りを小さくするため `log1p` で対数変換する．

#### 客室

`Cabin` の先頭文字を，`ABC`，`DE`，`FG`，不明の `M` にまとめる．客室情報が存在するかを `HasCabin` で表す．

#### 交互作用

客室等級ごとのOne-hot列と，女性かどうかを掛け合わせた列を作る．これにより，「女性であり，かつ3等客室である」といった組合せを線形モデルでも扱いやすくする．

#### グループ生存率

この実装の特徴的な処理は，同じチケットまたは同じ姓と客室等級を持つ女性・子どもの生存率を特徴量として使うことである．コード上の女性・子どもは，`IsFemale == 1` または敬称が `Master` の乗客を指す．

作成するグループ特徴は次の3種類を，チケット単位と姓・等級単位の両方について持つ．

- `WCRate*`：同じグループの女性・子どもの生存率
- `WCCount*`：計算に使えた同グループ人数
- `WCInfo*`：同グループ情報が存在したか

学習行では，自分自身の正解ラベルと人数を集計から除くleave-one-outを行う．自分の正解を自分の特徴量へ直接入れないために必要な処理である．

### 4.4 欠損値の補完

欠損補完に使う値は，交差検証の学習foldだけから計算する．

- `Age`：敬称と客室等級ごとの中央値，敬称ごとの中央値，全体中央値の順に使用する．
- `Fare`：学習側の中央値で補完する．
- `Embarked`：学習側の最頻値で補完する．

`AgeMissing` を追加するため，モデルは年齢が欠損していたこと自体も利用できる．補完後の年齢が14歳以下なら `IsChild=1` とする．

### 4.5 データリークを防ぐ仕組み

`fit_feature_state()` は，補完値，チケット件数，グループ生存統計などを学習側だけから計算する．`transform_features()` は保存された統計を検証データまたはテストデータへ適用するだけである．

交差検証では各foldについて次の順番を守る．

1. 学習foldだけで `fit_feature_state()` を実行する．
2. 学習foldを変換するときはleave-one-outを行う．
3. 検証foldには学習foldで得た統計だけを適用する．
4. 変換後の学習foldでモデルを学習し，検証foldを予測する．

この構造により，検証foldの正解や集計値が特徴量作成へ混ざることを防ぐ．

### 4.6 OOF予測と評価指標

OOF予測は，各乗客について「その乗客を学習に使っていないモデル」が出した予測である．`compute_oof()` は層化5-fold交差検証を行い，乱数シードを変えて4回繰り返す．

モデル比較には次の指標を使う．

- AP：生存者が少ない二値分類で，確率の順位付け性能を見る指標
- AUC：死亡者と生存者を確率で分ける能力を見る指標
- F1：適合率と再現率のバランスを見る正式評価指標

ハイパーパラメータ探索ではAPを使い，最終的な0または1への変換にはF1が高くなる閾値を使う．閾値は `0.10` から `0.90` まで `0.01` 刻みで調べる．最大の平均F1との差が `0.002` 以内にある閾値群の中央値を選ぶため，`0.385` のような値になる場合がある．

### 4.7 比較する6モデル

| モデル | 特徴 | 現在の主な採用設定 |
| --- | --- | --- |
| Logistic Regression | 線形な関係を学習しやすい | `C=3.0`，標準化あり |
| Random Forest | データを変えて作った多数の決定木を平均する | 600本，`min_samples_leaf=2` |
| ExtraTrees | 分割にも強い乱数を使う決定木アンサンブル | 600本，`min_samples_leaf=2` |
| HistGradientBoosting | 誤りを順番に補う決定木モデル | `max_iter=250` |
| LightGBM | 高速な勾配ブースティング決定木 | 300本，`num_leaves=7` |
| XGBoost | 正則化を備えた勾配ブースティング決定木 | 500本，`max_depth=3` |

ハイパーパラメータ探索は5-foldを2回繰り返し，探索用シード7で行う．最終OOF評価には別のシードを使い，探索時と評価時の分割を分ける．

### 4.8 シードバギング

木系モデルは乱数シードによって結果が少し変わる．`SeedBaggedModel` は同じ設定のモデルをシード42，142，242で学習し，予測確率を平均する．

この処理は6モデルすべてへ適用される．ロジスティック回帰は基本的に同じ結果になるため3回学習する必要性は小さいが，コード上は共通処理として扱われる．

### 4.9 全学習データでの再学習

モデル，ハイパーパラメータ，参加モデル，閾値を決めた後，712人すべてを使って前処理とモデルを学習し直す．その後，179人のテストデータについて各モデルの生存確率を計算する．

- スタッキングは6モデルの確率を2段目のロジスティック回帰へ入力する．
- ソフト投票は選ばれた5モデルの確率を平均する．
- 最良単一モデルはExtraTreesの確率をそのまま使う．

### 4.10 提出CSVの作成

`save_submission()` は，次の条件をassertで確認してからCSVを保存する．

- 列順が `PassengerId,Survived` である．
- 179行である．
- `PassengerId` に重複がない．
- すべてのIDが `test_titanic.csv` に由来する．
- `Survived` が整数の0または1である．

ただし，`save_submission()` は同名CSVが存在しても `to_csv()` で上書きする．再実行する場合は，既存の提出CSVを上書きしてよいか事前に確認する必要がある．

## 6．実行方法と注意点

### 6.1 実行方法

このディレクトリを作業ディレクトリとして環境を同期し，ノートブックを上から順に実行する．

```bash
uv sync
uv run jupyter notebook titanic_survival_prediction.ipynb
```

全モデルの探索と交差検証を行うため，実行には数分から十数分以上かかる可能性がある．

### 6.2 `answer.ipynb` の位置付け

`answer.ipynb` は正解配布後だけ使用する．提出CSVと正解を `PassengerId` で結合し，F1スコア，正解数，混同行列を表示する．不足または余分なIDについては警告するが，重複ID，179行，0／1整数を厳密に停止条件として検査するわけではない．提出形式の保証は本体ノートブック側の `save_submission()` で行う．

### 6.3 評価値を読むときの注意

- 探索用と最終評価用の分割シードは異なるが，同じ712人の学習データを繰り返し使用している．OOF値は未知テストデータの性能保証ではない．
- スタッキングの2段目は，先に作成した6モデルのOOF確率を使って評価される．厳密なnested stackingではないため，OOF F1に楽観性が含まれる可能性がある．
- 閾値の選択とF1の表示に同じ最終OOF予測を使うため，表示F1は閾値調整を含む比較値である．
- WC特徴を外すアブレーションは，WCありの3-seedモデルとWCなしの単一seedモデルを比較している．差のすべてをWC特徴だけの効果とは断定できない．
- OOF確率，探索結果，総合比較表はノートブックの変数とセル出力に保持され，別のCSVとしては保存されない．

## 7．要点

この実装は，Titanic向けの42特徴量，グループ生存率のleave-one-out，繰り返しOOF評価，シードバギングを組み合わせている．最終的には，6モデルを2段階で組み合わせるスタッキング，5モデルを平均するソフト投票，APで選んだExtraTrees単体という性質の異なる3提出を作る．

予測処理の中心は `titanic_survival_prediction.ipynb` であり，`main.py` は使用しない．正解データと `answer.ipynb` は事後評価専用であり，予測モデルの作成とは分離して扱う．
