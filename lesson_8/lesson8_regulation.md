# 第8回 Python Seminar：タイタニック号の生存予測コンペ

## 1. コンペの目的

配布されたタイタニック号の乗客データを使い、各乗客が生存したかどうかを予測する**二値分類モデル**を作成します。

- 学習データの目的変数：`Survived`
- `Survived = 0`：死亡
- `Survived = 1`：生存
- テストデータには `Survived` が含まれていません。
- テストデータの正解ラベルは、データリークを防ぐため**当日に配布**します。

学習データでモデルの作成・検証・改善を行い、最後にテストデータ179件の生存ラベルを予測してください。

## 2. 配布データ

使用するファイルは次の2つです。

| ファイル | 行数 | 列数 | 用途 |
| --- | ---: | ---: | --- |
| [`code/train_titanic.csv`](./code/train_titanic.csv) | 712 | 12 | モデルの学習と手元での検証 |
| [`code/test_titanic.csv`](./code/test_titanic.csv) | 179 | 11 | 当日の最終評価用の予測 |

`PassengerId` は学習データとテストデータの間で重複していません。両方を合わせると891件です。

### 2.1 各列の意味

| 列名 | 内容 | 補足 |
| --- | --- | --- |
| `PassengerId` | 乗客ID | 提出結果と乗客を対応付けるために必要 |
| `Survived` | 生存ラベル | 学習データのみに存在。`0`：死亡、`1`：生存 |
| `Pclass` | 客室等級 | `1`：1等、`2`：2等、`3`：3等 |
| `Name` | 氏名 | 敬称などを特徴量として抽出することも可能 |
| `Sex` | 性別 | `female` または `male` |
| `Age` | 年齢 | 1歳未満は小数。欠損値あり |
| `SibSp` | 同乗している兄弟姉妹・配偶者の人数 | 0以上の整数 |
| `Parch` | 同乗している親・子どもの人数 | 0以上の整数 |
| `Ticket` | チケット番号 | 数字以外も含むため、文字列として扱う |
| `Fare` | 運賃 | 0以上の数値 |
| `Cabin` | 客室番号 | 欠損値が多い |
| `Embarked` | 乗船港 | `C`：Cherbourg、`Q`：Queenstown、`S`：Southampton |

### 2.2 学習データのラベル分布

| `Survived` | 件数 | 割合 |
| ---: | ---: | ---: |
| `0`（死亡） | 439 | 61.66% |
| `1`（生存） | 273 | 38.34% |

クラス数に偏りがあるため、正解率だけでなく適合率と再現率のバランスも考えてください。

### 2.3 欠損値

CSVでは、欠損値は空欄になっています。

| 列 | 学習データ | テストデータ |
| --- | ---: | ---: |
| `Age` | 146件（20.51%） | 31件（17.32%） |
| `Cabin` | 552件（77.53%） | 135件（75.42%） |
| `Embarked` | 2件（0.28%） | 0件 |
| その他の列 | 0件 | 0件 |

欠損値をそのまま扱えないモデルもあります。削除、代表値による補完、欠損を示す特徴量の追加などを検討してください。前処理は、検証データやテストデータの情報が学習側へ漏れないように実装する必要があります。

## 3. 提出形式

テストデータ179件に対する予測を、次の2列を持つCSVとして出力してください。

```csv
PassengerId,Survived
154,0
753,1
```

提出CSVは次の条件をすべて満たす必要があります。

- 列名は `PassengerId` と `Survived` にする。
- テストデータの179件を、過不足なく1件ずつ含める。
- `PassengerId` はテストデータの値をそのまま使用する。
- `Survived` は整数の `0` または `1` にする。
- 生存確率を出力するモデルでは、しきい値を決めて `0` または `1` に変換する。
- 行の並びだけに依存せず、評価時は `PassengerId` で正解データと対応付ける。

CSVのファイル名は指定していません。どのモデルの提出結果か判別できる名前を付けてください。

## 4. 評価方法

最終順位は、`Survived = 1`（生存）を正例とした**F1スコア**で評価します。値が大きいほど高評価です。

F1スコアは、適合率（Precision）と再現率（Recall）の調和平均です。

```text
Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
F1        = 2 × Precision × Recall / (Precision + Recall)
```

- `TP`：生存者を生存と正しく予測した件数
- `FP`：死亡者を生存と誤って予測した件数
- `FN`：生存者を死亡と誤って予測した件数

予告スライドに掲載されている評価コードの画像では `accuracy_score` を使用していますが、**本コンペの正式な評価指標はF1スコア**です。当日配布する答え合わせ用コードも、F1スコアを計算するものを使用してください。

## 5. コンペのレギュレーション

### 5.1 使用できるデータ

- 使用できるのは、配布された `train_titanic.csv` と `test_titanic.csv` のみです。
- 配布された列から新しい特徴量を作ることは可能です。
- 学習データを訓練用と検証用に分割することや、交差検証を行うことは可能です。

### 5.2 禁止事項

- 外部データを追加して学習・推論すること。
- Kaggleなどで公開されている元のTitanicデータや、別のTitanicデータセットを参照・結合すること。
- インターネット、他の教材、リポジトリ内の別データなどから、テストデータの正解ラベルを検索・照合・推測して持ち込むこと。
- `PassengerId`、`Name` などを使って、外部の正解ラベルを調べること。
- 当日より前に正解ラベルを入手した場合、それを閲覧または利用すること。
- モデルの予測ではなく、人手でテストデータのラベルを書き換えること。
- LLMを分類モデルまたは推論パイプラインの一部として組み込むこと。

> [!IMPORTANT]
> Titanicデータには、正解ラベルを含む類似データがインターネットや既存教材で公開されています。しかし、それらとの照合はデータリークであり、本コンペでは禁止です。テストデータの正解ラベルは当日まで未知のものとして扱ってください。

### 5.3 モデルと提出数

- モデルは、配布された学習データを使って各自で0から学習させてください。
- 使用するアルゴリズムやライブラリに制限はありません。ただし、上記のデータとLLMに関する規則を守ってください。
- 提出できるモデルは、1人あたり最大3個です。
- 提出するモデルはいずれも公開対象です。使用したモデル、前処理、特徴量、ハイパーパラメータを説明できるようにしてください。
- 乱数のシード値は自由です。結果を再現できるよう、コード内に記録することを推奨します。

### 5.4 アンサンブル

複数モデルの予測値を組み合わせることは可能です。例えば、次の方法があります。

- 多数決（hard voting）
- 予測確率の平均や重み付き平均（soft voting）
- スタッキング

最終的な `Survived` は、モデルから得られた予測値を使って決定してください。アンサンブルを1つの提出モデルとして数える場合を含め、提出数は最大3個です。

## 6. 推奨する進め方

1. データ型、ラベル分布、欠損値、カテゴリ数を確認する。
2. `train_titanic.csv` を訓練用と検証用に分割する。
3. 欠損値補完、カテゴリ変数のエンコーディング、特徴量作成を行う。
4. ベースラインモデルを学習し、検証データのF1スコアを確認する。
5. 特徴量、モデル、ハイパーパラメータ、判定しきい値を改善する。
6. 必要に応じて交差検証やアンサンブルで汎化性能を確認する。
7. 採用する方法を学習データ全体で再学習し、テストデータを予測する。
8. 提出CSVの列名、行数、IDの重複・過不足、予測値を確認する。

検証時には、ラベル比率を保つ層化分割（stratified split）を推奨します。前処理も含めて交差検証する場合は、`Pipeline` などを使い、補完やエンコーディングを各訓練foldだけで学習してください。

## 7. 改善のヒント

- ロジスティック回帰や決定木など、単純なモデルを最初の基準にする。
- `Sex`、`Embarked` などのカテゴリ変数をOne-hot encodingする。
- `Age`、`Cabin`、`Embarked` の欠損値を適切に扱う。
- `SibSp` と `Parch` から家族人数などの特徴量を作る。
- `Name` から敬称、`Cabin` からデッキ、`Ticket` から接頭辞や同一チケット人数などを抽出する。
- XGBoost、LightGBMなどの勾配ブースティング決定木を試す。
- F1スコアが最大になる判定しきい値を、学習データ内の検証予測だけを使って検討する。
- 単一の分割結果だけで判断せず、交差検証の平均とばらつきを確認する。
